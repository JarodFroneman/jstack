## Canonical provenance artifacts

- `mcp/jstack/upstream/gstack/provenance-plan.v1.json` is the reviewed,
  human-authored mapping from pinned source paths to adaptation disposition and
  local targets.
- `mcp/jstack/upstream/gstack/provenance.v1.json` is deterministic
  generated output containing source and local-target digests.
- `mcp/jstack/upstream/gstack/provenance.py` validates the closed contract,
  immutable pin, plan binding, source inventory, target safety, and freshness.
- `scripts/build_gstack_provenance.py` writes or checks the manifest.
- `THIRD_PARTY_NOTICES.md` records attribution and the applicable licence
  notice.

The four disposition classes remain explicit:

| Class | Treatment |
| --- | --- |
| A | Adapt general method into original JStack-native contracts |
| B | Consider or implement a bounded optional provider wrapper |
| C | Reject duplicate control-plane, state, permission, or release authority |
| D | Defer or reject out-of-scope, costly, mutable, or unsupported surfaces |

`MIXED` records document cross-cutting sources whose individual surfaces have
different treatments. `RESEARCHED`, `ADAPTED`, and `WRAPPED` describe what
JStack did; none makes upstream content an instruction authority.

## Review and update procedure

An upstream update is a new engineering change, not routine package refresh:

1. Resolve the exact candidate commit and tree in an isolated checkout.
2. Verify the upstream licence and hash the licence file.
3. Diff the old and new source inventories, prompts, runtimes, dependencies,
   state paths, network behavior, installers, host generators, providers, and
   security boundaries.
4. Reclassify every affected provenance record and document any changed
   adaptation, rejection, or deferral decision.
5. Update original JStack contracts only where separately approved; do not
   copy prompt bodies, permissions, state, or control-plane behavior by
   default.
6. Update the plan pin and local targets, then regenerate the manifest against
   the exact checkout.
7. Run focused adaptation tests, contract compatibility, Product Boundary,
   artifact synchronization, provenance, compilation, and the proportionate
   full verification suite.
8. Review migration, privacy, provider, host, security, cost, and rollback
   effects.
9. Obtain separate commit, publication, release, installation, or deployment
   authority if any such action is requested.

Canonical commands for an already reviewed pinned checkout are:

```text
python3 scripts/build_gstack_provenance.py --write --source-root <pinned-gstack-checkout>
python3 scripts/sync_artifacts.py --write
python3 scripts/build_gstack_provenance.py --check --source-root <pinned-gstack-checkout>
python3 scripts/sync_artifacts.py --check
```

The source root must resolve to the commit and tree encoded in the plan.
`--write` regenerates evidence; it does not approve the underlying adaptation.

## Failure and staleness behavior

Verification fails closed when the repository, commit, tree, licence, source
inventory, plan digest, source digest, local-target path, local-target digest,
record identity, or generated bytes differ. Unsafe and missing local targets
are rejected. A changed local implementation is stale until the reviewed plan
and generated manifest are current.

Provider or host availability is independent from provenance freshness. A
current manifest does not prove runtime safety, semantic correctness, or
release readiness; it proves only the recorded source/target identity and
review mapping.

## Licensing and attribution

gstack is MIT licensed at the recorded pin. Preserve the copyright and MIT
notice for material actually reused. The current records primarily document
research and original JStack re-expression; they explicitly state when prompt,
runtime, state, installer, or provider code was not copied.

Any source with a different or unclear licence requires fresh legal/licence
review before adaptation. Provenance metadata must never imply permission
beyond the source licence.

## Rollback

Rollback restores the previously released JStack plugin as a complete unit,
including its provenance plan, manifest, notices, schemas, generated copies,
and receipts. Do not mix a new plan with an old manifest or selectively copy
generated plugin files. Invalidate receipts bound to the replaced catalog,
policy, provider, host, or candidate digest.

No automatic updater or enterprise auto-sync is part of this candidate.
