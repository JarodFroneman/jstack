# Migrating to JStack 0.10.0-beta.6.1

Beta.6.1 is a compatibility-preserving Prompt Compiler amendment on top of
Beta.6 Product UI Motion Enforcement. It adds no slash command, MCP tool,
model-provider call, runtime dependency, persisted-state migration, or action
authority.

## What changes

- Prompt Compiler advances to `1.1.0`; the deterministic execution template
  advances to `jstack.codex-execution-prompt.v2`.
- Every official workflow receives an always-traced professional
  prompt-engineering standard: objective, bounded, repository-grounded,
  enterprise-professional, concise for small work, progressively staged only
  where complexity warrants it, and resistant to generic filler, invented
  requirements, dependency churn, and low-quality AI output.
- Authorized implementation/fix work and explicit plan-only creation of new
  software or a development workspace receive a proportionate
  secure-development baseline.
- `jstack-professional-standard` and `jstack-secure-development` are reserved
  policy requirement identifiers and cannot be replaced by caller grounding.
- All six commands, 59 canonical tools, 52 frozen aliases, public schemas, and
  existing Prompt Compiler approval semantics remain compatible.

## Authority and security boundaries

The quality calibration is not evidence of expertise and grants no authority.
The secure-development baseline stays inside the compiled action envelope,
preserves Audit and Evidence Builder read-only floors, and does not turn an
explanation, ordinary plan, deployment, or production operation into code
implementation.

Security checks are proportionate to risk. `jstack_security_audit` is used for
substantial or sensitive authorized implementation. Independent scanner or
human evidence remains mandatory only where the active risk and release policy
requires it. An optional skipped check is disclosed with residual risk and is
never represented as passing evidence. JStack does not claim attack immunity.

## Upgrade

1. Retain the complete Beta.6 MCP, source, cache, marketplace, configuration,
   and plugin inventory as one rollback unit.
2. Install from the exact annotated `v0.10.0-beta.6.1` GitHub prerelease tag.
3. Keep all six dedicated plugins and the MCP on the same Beta.6.1 version.
4. Keep the umbrella plugin absent and Beta.6 installed but disabled.
5. Restart Codex or open a fresh task.
6. Verify MCP version `0.10.0-beta.6.1`, 59 canonical tools, 52 frozen aliases,
   six enabled plugins, exact source/cache parity, and JSONL smoke behavior.
7. Verify all six workflows render the professional standard; code/new-project
   cases render the secure-development baseline; read-only and unrelated cases
   do not; and the complete final prompt still requires exact user approval.

Use isolated side-by-side MCP, marketplace, and cache namespaces. Do not
replace an in-use Beta.6 runtime path.

## Receipt invalidation

Prompt preview, compilation, context, planning, loop, program, UI, and release
receipts remain session-, policy-, project-, and server-version-bound. Recreate
them after upgrading. No persisted loop, program, mastery, or private UI
evidence migration is required.

## Rollback

Restore the complete Beta.6 deployment unit and restart Codex. Do not mix MCP,
plugin source, cache, marketplace, or configuration versions. Preserve
`~/.jstack` state; Beta.6.1 adds no state migration.

This remains an unvalidated prerelease. It claims deterministic implementation,
compatibility, and test evidence, not measured prompt-quality uplift,
production readiness, or completion of the deferred Beta.1 Proof Study.
